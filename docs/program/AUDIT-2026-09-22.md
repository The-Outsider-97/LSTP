## Scope and evidence

All 41 tracked files were inventoried, including every file in `docs/`, `spec/`,
`src/lstp/`, and `examples/`, plus README, license, ignore file and packaging.
`baseline-inventory.json` records byte counts and SHA-256 digests. The PDF was
extracted with Poppler and its canonical syntax on page 19 was visually checked.
The PDF and Markdown describe the same competing canonical model; Markdown is
not an independent authority. This is an initial audit, not the fresh final audit.

The 17 Python files, all 10 examples, `pyproject.toml`, `spec/lattice.bnf`, and
`spec/packet-schema.json` each contained exactly one newline. Empty ASTs have no
executable protocol behavior. No tests, CI workflows, configuration, benchmarks,
runtime, carrier implementation, launcher or release tooling existed. Some modules
named in README/Whitepaper do not exist even as scaffolds. MIT licensing exists;
the ignore file only addressed Jekyll/Ruby artifacts.

Running `json.loads` on the original schema failed at line 1 column 1 because it
began with `# JSON Schema for canonical packet`. Removing that heading is a
syntax-only correction, not endorsement of the schema's disputed semantics.

## Initial risk assessment

1. Critical interoperability risk: two incompatible contracts both call themselves
   v0.1. A green schema test would not resolve this.
2. Critical permission risk: case conversion or vocabulary aliases could erase
   forbids/confirmation/review/logging or introduce unattended execution.
3. High training risk: no stable grammar/schema/canonicalization mapping exists.
4. High completeness risk: examples and runtime are absent; no independent
   implementation demonstrates cross-implementation agreement.
5. Reproducibility risk: publication source assets are missing; Python matrix and
   dependency/build reproducibility must be verified rather than assumed.

## Decision log

- D-001: Follow PDF > README > technical artifacts > code, as mandated. A newer
  subordinate file does not silently supersede the PDF.
- D-002: Do not mutate the authoritative PDF or invent missing canonical rules in
  the first increment. Prepare the smallest canonical mapping resolution next.
- D-003: Repair schema JSON syntax only. Meta-schema validity is structural
  evidence, explicitly not protocol conformance.
- D-004: Implement generic bounded JSON inspection first; export no `validate`
  command that could falsely certify a packet.
- D-005: Separate engineering tests from a failing protocol-readiness CI gate.
  No xfail, skipped core tests, or continue-on-error disguises missing conformance.
- D-006: Input resource limits and decimal decoding are a development-tool profile,
  not a frozen wire numeric range or byte-canonical serialization contract.
