## Work completed

### Canonical semantic boundary

Added `src/lstp/models.py` with an immutable `Octad` containing exactly the eight authoritative semantic domains in their defined order: pragmatics, atoms, relations, context, confidence, permissions, evidence and output. Added a separate `PacketEnvelope` for packet identity, protocol version, carrier, audit and extension metadata. `PacketEnvelope.semantically_equals()` compares only Octad content so transport/envelope identity is not accidentally folded into semantic equality.

The model deliberately leaves disputed subfield contracts opaque. It does not encode the currently conflicting schema permission vocabulary, infer carrier syntax, grant authority, or claim byte-canonical serialization. Input containers are recursively snapshotted into immutable JSON-like structures to prevent caller mutation from changing semantic content after construction.

### Grammar ambiguity removal

Reconciled two strict-core ambiguities directly against `spec/operator-table.md`:

1. Outside target scope, leading `-` is unary exclusion. Signed numeric and period literals are now confined to scope syntax; general expressions use `unsigned_number`. This removes the previous double parse of values such as `-1` as both unary exclusion and a signed primary literal.
2. `%` is packet-level confidence in core v0.1. Confidence attachment was removed from postfix terms, claims and weighted alternatives. The grammar therefore no longer silently chooses relation-/claim-specific confidence semantics that the operator table explicitly reserves for a future vocabulary.

`inline_modifier` likewise no longer accepts a confidence clause as a term-level modifier. Packet-level confidence remains available as a top-level clause and in the packet-level main-clause tail.

### Regression tests

Added `tests/test_models.py` for Octad ordering, immutable snapshots, envelope/semantic equality separation, identity/version preconditions and rejection of unsupported runtime objects.

Added `tests/test_grammar_contract.py` to pin the exclusion/signed-scope distinction and packet-level-only confidence contract.

## Problems discovered / self-review

- The prior grammar allowed `-1` to be interpreted through both unary exclusion and signed-number paths despite the operator table explicitly assigning signed literals to scope and unary `-` to exclusion outside scope.
- The prior grammar allowed `%` on postfix expressions, claims and weighted alternatives even though the operator table states that core v0.1 packet confidence must not be guessed as relation-/claim-specific confidence.
- The current JSON Schema remains materially inconsistent with the authoritative canonical field definitions: its pragmatics, atom representation, context requirements, confidence shape, permission vocabulary, evidence and output fields are not yet reconciled.
- The new Python Octad model intentionally does not validate those disputed substructures. Treating opaque containers as validated canonical semantics would be an overclaim.
- `PacketEnvelope` currently establishes separation, not a final canonical envelope contract. Version negotiation and envelope serialization remain unresolved.

## Specification consistency

Resolved at grammar level:

- Operator-table §5.4 versus grammar signed-expression ambiguity: grammar now gives `-` one strict-core meaning outside scope and retains signed literals in scope.
- Operator-table §8.1 versus grammar confidence attachment ambiguity: core grammar now exposes packet-level confidence only.

Still unresolved:

- Whitepaper canonical Octad subfields versus `spec/octad_schema.json` draft shapes.
- Whitepaper permission modes (`RO`, `RW`, `EXEC`, `PREVIEW`, `COMMIT`, `SUGGEST`) versus lower-case schema modes and older subordinate permission artifacts.
- Canonical expanded Octad Lattice form versus the compact clause grammar.
- Stream packet separator and exact canonical serialization/equality profile.

## Security and reliability findings

- Keeping permissions opaque in the new semantic container prevents the Python model from accidentally treating a serialized permission mode as granted authority.
- Immutable semantic snapshots reduce mutation-after-validation/time-of-check-to-time-of-use risk in later validation pipelines.
- Removing ambiguous confidence attachment prevents a parser from manufacturing more specific epistemic semantics than the sender supplied.
- Removing signed-expression ambiguity prevents tokenizer/parser precedence from silently changing exclusion semantics.

No runtime authorization path has been added; LSTP packet permissions still grant no host authority.
