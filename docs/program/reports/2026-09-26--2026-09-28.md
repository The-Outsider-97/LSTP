## Work completed

Self-review of the newly introduced canonical model found two determinism/interoperability defects in `_freeze`:

1. mapping keys were coerced with `str(key)`, which could collapse distinct host-language keys such as integer `1` and string `"1"` into the same canonical key;
2. arbitrary Python floats were accepted, including NaN and positive/negative infinity, even though those values are outside the JSON number model and are not portable across JSON carriers.

`src/lstp/models.py` now enforces a strict JSON-value boundary. It rejects non-string object keys, rejects non-finite floating-point values, recursively validates nested values, and includes a structural path in diagnostics. The immutable snapshot behavior and semantic/envelope separation from the prior cycle are retained.

`docs/program/DECISIONS.md` now records D-013. This is deliberately scoped as an implementation boundary, not a canonical-byte or numeric-precision rule. Number precision, Unicode normalization, object ordering, textual formatting, and canonical bytes remain unresolved and are not inferred.

## Problems discovered

The prior canonical-model implementation was too permissive at the host-language boundary. Converting mapping keys to strings was particularly unsafe because it could silently alter semantic identity before validation or serialization. Accepting NaN/Infinity also undermined deterministic cross-carrier behavior.

The larger protocol blocker remains unchanged: `spec/octad_schema.json` still encodes subordinate/draft field shapes that materially conflict with the authoritative Whitepaper, especially pragmatics, atoms, context, permissions, evidence, and output. It must not become the semantic validator contract merely because it is machine-readable.

## Specification consistency

No authoritative semantics were changed this cycle. D-013 narrows accepted Python runtime values to the JSON data model and explicitly avoids defining unresolved serialization semantics.

Outstanding conflicts remain:

- SPEC-001: canonical Octad/framed/named/stream grammar versus compact EBNF;
- SPEC-002: authoritative Octad field semantics versus current JSON Schema shapes;
- SPEC-003: authoritative permission modes/constraints versus subordinate permission/schema vocabulary;
- SPEC-004: envelope identity versus semantic context linkage and equality rules;
- stream `packet_sep` terminal remains undefined by the authoritative source;
- duplicate packet-level confidence conflict behavior remains undefined.

## Security and reliability findings

Fail-closed behavior improved at the canonical model boundary. Malformed host values are rejected rather than normalized. This prevents key-collision coercion and prevents non-portable IEEE-754 special values from entering semantic equality.

Diagnostics expose only the structural path and type/category of the malformed value; they do not echo arbitrary payload content.

No runtime execution authority was added. Permission data remains inert requested-authority data.
